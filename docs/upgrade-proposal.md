# 配额曲线机制升级设计方案

日期：2026-11-24。对象：BNB 主网第一册（不可升级、无 owner）之后的第二册。本文是设计，不是上线说明。文中的原型只在本地 forge 里跑过，没有部署，没有广播，没有使用私钥。

证据从哪来：本次环境里没有挂上 `census-curve-src.tgz`，所以现有机制不是从 `docs/agent-id-mechanisms.md` 抄的，是从主网字节码、函数选择器和 `eth_call` 读出来的。读取用的是 `https://bsc-dataseed.bnbchain.org`，只调用了 `eth_getCode`、`eth_call`、`eth_getStorageAt`、`eth_getBlockByNumber`、`eth_gasPrice`、`eth_chainId`。选择器名字来自公开签名库的碰撞，文中会标明哪些名字是库里对上的、哪些只是字节码行为。

## 1. 第一册是什么，为什么它现在显得一般

第一册是一条写死的线性联合曲线，外面套了一道 Agent ID 门，再挂了一个还没有储备的 0.3% 恒定乘积池。

工厂 `0x08A7FB944d16a9f8cb7031e0D756d7B5Be13B87c` 的 `create(string,string)` 部署三联合约。`markets(uint256)` 返回代币、曲线、池子三个地址。`marketCount()` 目前是 1。`AGENT()`、`BASE()`、`SLOPE()` 都是常量。工厂、代币、曲线、池子都没有 `owner()`。编译器元数据是 solc 0.8.26。

第一册：

| 角色 | 地址 | 读到的事实 |
| --- | --- | --- |
| 代币 | `0x69043d39ad5D8F2Bb5Bc16b913B0526E444bdB18` | 名称「配额曲线第一册」，符号 QTA，18 位小数。`factory()` / `curve()` / `pool()` / `agent()` 指向上表和注册表 |
| 曲线 | `0xa298EA6d338a923e452A84A77a584852cD37308B` | `base()` = `slope()` = `1e15`。`SCALE()` = 100。选择器 `0x9ded419b` 返回 `100e18`，这就是 100 枚的上限常量（公开签名库没有收录这个名字） |
| 池子 | `0x586AfadF10f101B8C7E2Fc0eee33103EC649f418` | `MINIMUM_LIQUIDITY()` = 1000。字节码里有 `997` 和 `1000`，即 Uniswap V2 那种 0.3% 公式。`bnbReserve()` 和 `tokenReserve()` 都是 0 |
| 注册表 | `0x60B9262456dE011F7d15a54CdD8c48bAaa8B022F` | 名称 SPACE ID Agent ID，符号 AI。它自己有 owner，那是注册表的管理员，不是曲线的管理员 |

曲线报价和第一枚的价格对得上。供给为 `S`、再铸 `a`（都用 1e18 为 1 枚）时：

```text
支付 = base * a / 1e18 + slope * (2 * S * a + a * a) / (2 * 1e36)
```

`S = 0`、`a = 1e18` 时支付是 `1.5e15`，也就是 0.0015 BNB。本次读取时 `supply()` 是 `1e18 + 5`，`quoteMint(1e18)` 返回 `2.5e15`，`quoteSell(1e18)` 返回 `1.5e15`，`reserve()` 是 `1.5e15`。边际价格 `base + slope * S / 1e18`，当时是 `2e15`。从 0 铸到 100 枚的积分合计是 5.1 BNB。

已核对的曲线入口：`mint(uint256)`、`sell(uint256)`、`quoteMint(uint256)`、`quoteSell(uint256)`、`supply()`、`base()`、`slope()`、`marginalPrice()`、`reserve()`、`SCALE()`、`agent()`、`token()`，以及按地址读的 `mintedOf`、`quotaOf`、`remaining`（这三个名字来自签名库）。铸路径会读注册表。池子入口包括 `swap(bool,uint256,uint256)`、`quoteSwap(bool,uint256)`、`addLiquidity(uint256,uint256)`、`removeLiquidity(uint256,uint256,uint256)`、`lpSupply()`、`lpOf(address)`、`priceBnbPerToken()`。池子字节码里有 `NotAgent()`，交换同样要过身份。`quoteSwap` 现在回退 `0xc301e07e`，因为池子是空的。

另外两件从字节码读到的行为：

- `quoteMint(1)` 在当前供给下是 0，`quoteMint(1000)` 是 2 wei。积分向下取整，很小的数量可以不付钱铸出来。供给里多出来的 5 wei 和这件事一致。
- 选择器 `0xb399b0bc`（签名库里的 `remaining(address)`）对一个还没入册的地址返回 `100e18 * 100 / (100 + 槽2)`。当时槽 2 的值是 6（选择器 `0x2e52d606` 与 `n()` 相符），返回 `94339622641509433962`，大约 94.34 枚。选择器 `0x04e22101` 与 `QuotaExceeded()` 相符，说明铸的时候有配额检查。按这个预览，先来的地址仍能拿走几乎整册。

站在用户这边，这套东西做完就结束了。付 0.0015 BNB 得到 1 枚 QTA，价格沿一条直线慢慢上去，没有下一块、下一分钟要回来看的东西。Agent ID 只是一道门：有就进，没有就回退。进来之后，这个身份没有席位，也没有「这一块记的是谁」。池子在界面上存在，链上储备是 0，交换失败。100 枚、全程大约 5.1 BNB 的盘子，一个人的配额预览却有 90 多枚，册子不像在点名。

站在传播这边，它没有一个可以复述的句子。听到的是「持有币安 Agent ID 才能买的联合曲线」。同一条链上，Flap 的 Agent ID 门、Gang 的代理钱包曲线，已经是这个句子。0.45 秒一个块，页面上没有任何东西跟着块走，截图里只有一条静态价格。黑客松创新奖要至少 30 个 Agent ID 地址真的来交互。第一册的门禁不制造「必须换一个身份」的动作，一个地址就能把额度打得很深。

所以要升级的不是斜率，是时钟和身份的单位。块是时钟。Agent ID 的 `tokenId` 是名册上的一行，而不是一把钥匙。

实测 gas limit 已经是 80,000,000，高于 Fermi 文本里的 55M。设计按实测的 80M 和 0.45 秒来留余量，不按 55M 去卡交易。

和机制有关的三个数：

- 1 块约 0.45 秒。人点不中单独的一块。代理程序有机会，构建者也有机会。
- 1 个验证者轮次 = 16 块 = 7.2 秒。这是开册后的狙击保护长度。
- 10 个轮次 = 160 块 = 72 秒。这是推荐方案的一个窗口。

BEP-619 写过：0.45 秒加上一轮只有 7.2 秒，搜索者和构建者的配合窗口变窄。Pasteur 之后块主要由构建者提交。衰减到地板的那一块，可能被构建者拿走。这是风险提示里要写的事实，不是要去跟构建者抢排序。

## 3. 这里的 hook 指什么

Uniswap v4 的 hook 是池子在交换、加减流动性前后回调的合约。和这次有关的是 `beforeSwap`：它可以改这一笔的手续费，也可以改交换结果。社区里用它做过动态费、限价、按时间切片的 TWAMM，以及按块结算的拍卖。

BNB 链上已经有同类池子：PancakeSwap Infinity。CLPoolManager `0xa0FfB9c1CE1Fe56963B0321B32E7A0302114058b`，Vault `0x238a358808379702088667322f80aC48bAd5e6c4`（[地址表](https://developer.pancake.xyz/contracts/infinity/resources/addresses)）。官方的 hook 例子在 `beforeSwap` 里返回 `lpFee | OVERRIDE_FEE_FLAG`，按身份改手续费（[开发指南](https://developer.pancake.xyz/contracts/infinity/guides/develop-a-hook)）。那个例子用 `tx.origin` 判断 veCake。第二册不学这一点：Agentic Wallet 可以是合约账户，`tx.origin` 会把真正持有 Agent ID 的钱包认错，也会把检查从钱包挪到外层调用者。第二册只认 `ownerOf(agentId) == msg.sender`。

第一册的池子是自己写的 0.3% 恒定乘积，不是 Infinity 池。第一期把同样的 `beforeSwap` 语义做进第二册自己的池子：交换前先看本块已经成交了几笔、这个 `tokenId` 是不是本窗口的席位，再决定费率。Pancake Infinity 上的同名 hook 留作第二期。黑客松截止前不把外部池子管理器当成关键路径。

三套方案共用同一条费率，差别在谁能享受「不加拥挤费」：

```text
extra = 本块已成交笔数 * 10 bps
席位本人：extra = 0
其他已通过身份检查的人：extra = extra / 2
费率 = min(100 bps, 30 bps + extra)
```

30 bps 是第一册池子的 0.3%。拥挤费每块从 0 起算，下一块的第一笔重新从 30 bps 开始。计数放在存储里，键是 `block.number`。EIP-1153 的临时存储只活在一笔交易内部，跨不了同一块里的下一笔交易，所以不能用它做块内拥挤。

没有对应 `tokenId` 的调用者进不了铸，也进不了交换。费率留在池子储备里，不打到团队地址。

开册后的前 16 块，三套方案都不允许铸。这是首块狙击保护，长度等于一个验证者轮次。

## 4. 三套候选

三套都保留第一册的线性地板，这样第二册仍然是配额曲线，而不是另一套发行。1 枚 = `1e18`。第 `filled` 席（从 0 数）的地板：

```text
floor = 1e15 + 0.5e15 + 1e15 * filled
```

第 0 席 0.0015 BNB，第 1 席 0.0025 BNB，第 99 席 0.1005 BNB。100 席的地板之和是 5.1 BNB。

三套共用的身份规则：调用者传入自己的 `agentId`，合约要求 `ownerOf(agentId) == msg.sender`，并且这个 `tokenId` 在这一册里只能铸到 1 枚。身份可以转让，冷却绑在 `tokenId` 上，不绑在地址上。租来的身份仍然只能坐一次。合约分辨不了真人，这一点写在风险提示里。

### 方案 A · 节拍放量

每一拍放出 1 枚铸额。一拍 = 16 块 = 7.2 秒。没人领，铸额留在账上。同一拍里，不同的 Agent ID 可以各领 1 枚，直到这一拍积下来的额度用完。价格就是当时的地板，没有窗口溢价。

用户看到一条按拍跳动的配额条：本拍还剩几枚，下一拍倒计时同时写着块数和大约多少秒，自己的 Agent ID 是否已经入过册。交换按钮旁边写着本块已成交笔数和这一笔的费率。

一次流程：

1. 用户自己打开钱包，页面只读 `ownerOf`。不收集配对码，不代登录。
2. 页面显示 `claimable = min(已过去的拍数 + 1, 100) - 已铸枚数`。开册 16 块之内这个数是 0。
3. 用户提交 `claim(agentId)`，支付恰好等于当前地板的 BNB，得到 1 枚。
4. 之后可以 `sell` 按积分卖回，或在池子里 `swap`。卖回按顶层积分，可能高于或低于他当初付的地板，因为先铸的人若在供给变高时卖出，退回的是当时的顶层，不是他自己那一层。这句话放进风险提示，不放进宣传句。

合约：

```solidity
function claim(uint256 agentId) external payable returns (uint256 price);
function bank() external view returns (uint256 claimable, uint256 tick, uint256 nextTickBlock);
function beforeSwap(uint256 agentId) external returns (uint24 feeBps);
```

状态：`openBlock`、`filled`、`reserve`、`usedId[tokenId]`、`minterOf[tokenId]`、`congestionBlock`、`swapsInBlock`，以及池子的两份储备。

每一块的计算：

```text
tick = (block.number - openBlock - 16) / 16     // 保护期内不可铸
unlocked = min(tick + 1, 100)
claimable = unlocked - filled
price = floor(filled)
```

同一块里的第 `k` 笔交换（`k` 从 0 计）用上面的费率公式。本方案没有「本窗口唯一席位」，不加拥挤费的人是这一册里已经入册的 `tokenId`。其他持有 Agent ID、但还没入这一册的地址，承担一半拥挤加价。没有 `tokenId` 的调用直接回退。

离不开 Agent ID：每一枚铸出都写死一个 `tokenId`，同一个 id 不能再铸。名册是身份的列表，不是地址的列表。把检查换成普通白名单之后，这本册就不再是 Agent 点名。

防刷、防机器人：一 id 一枚，没有积分、没有返还、没有按交易量累的任何计数奖励。积压的额度一次只能领 1 枚，一笔交易抽不干。开册前 16 块不能领。不使用 `tx.origin == msg.sender`。机器人可以在新的一拍开始时抢第一枚，它付的仍是地板，没有更低的价格可抢。页面在额度是 0 时把按钮关掉，避免无意义的失败交易。

评分（设计判断，不是评委打分）：

| 项 | 分 | 理由 |
| --- | --- | --- |
| 深度 30 | 22 | 出块释放和块内费率是真状态机，身份也落在 tokenId 上。拍子本身比较直 |
| 实用 25 | 22 | 额度会等用户。不和别人抢同一秒。7.2 秒一拍，倒计时看得懂 |
| 完整 25 | 23 | 最靠近第一册，工厂、曲线、池子、风险条都能在截止前做完 |
| 创新 20 | 13 | 「每 7 秒多 1 枚额度」能讲，不容易被复述成一件新闻 |
| 合计 | 80 | |

风险和 gas：一拍的开头仍是延迟竞争，构建者可以卡在拍子切换的那一块。价格没有衰减，所以抢到和晚到付的一样多，输的是「这一拍还有没有额度」。gas 与下面原型里的占席同级，少一次对外转账，首次冷存储大约 20 万 gas 出头。按实测 `0x2faf080` = 0.05 gwei，20 万 gas 约 0.00001 BNB，约为第 0 席地板 0.0015 BNB 的一百五十分之一。早期几席的主要成本是地板和溢价，不是 gas。按钮旁仍要写明气费另计，但不要再写成气费高于曲线。

### 方案 B · 轮次席位（推荐）

每 160 块一个窗口，约 72 秒，正好 10 个验证者轮次。一个窗口只成交一个 Agent ID。窗口第 0 块的价格是 2 倍地板，之后每一块下降，最后一块等于地板。空窗口不消耗名额，下一窗继续卖下一席。同一个 `tokenId` 整册只能坐一次。高出地板的溢价在同一笔交易里转到死地址 `0x000000000000000000000000000000000000dEaD`，不进曲线储备，不进团队钱包，也不分给持有人。

用户看到一个大倒计时：这一窗还剩多少块、大约多少秒，当前价格，地板是多少，溢价是多少，本窗席位是空的还是已经写上了哪个 Agent ID。价格旁边有一张小表，列出「现在付 / 等到最后一块付」。交换区显示本块成交笔数。若你就是本窗席位，费率固定 30 bps；别人会看到自己的拥挤加价。

一次流程：

1. 用户用自己的钱包连接。页面读取他指定的 `agentId`，核对 `ownerOf`。核对失败就停，不引导他去登录 Agentic Wallet。
2. 保护期（部署块之后的 16 块）按钮不可用，文案写「开册保护，还剩 N 块」。
3. 保护期过后，用户看价格和风险提示，提交 `takeSeat(agentId)`，`msg.value` 大于等于当前价格。多付的部分退回。
4. 合约铸出 1 枚，把地板记入曲线储备，把溢价转给死地址，把这一窗标成该 `tokenId`。
5. 之后 `sell(1e18)` 只退回这一枚在曲线顶层的积分，不退溢价。也可以把代币放进池子再交换。

数字例子，第 0 席：

| 窗口内第几块 | 价格 | 进储备 | 进死地址 |
| --- | --- | --- | --- |
| 0 | 0.0030 BNB | 0.0015 | 0.0015 |
| 159 | 0.0015 BNB | 0.0015 | 0 |

立刻卖回：退 0.0015 BNB。在第 0 块占席的人净付出 0.0015 BNB 溢价加上 gas。等到最后一块，溢价是 0，净付出是 gas。第 1 席的地板是 0.0025 BNB，窗口开头是 0.005 BNB。

合约（与 `src/proposal/TurnSeatBook.sol` 一致，工厂是薄封装，见第 6 节）：

```solidity
function clock(uint256 blockNumber) external view returns (bool open, uint256 window, uint256 elapsed);
function floorPrice(uint256 filledSeats) external pure returns (uint256);
function dutchPrice(uint256 floor, uint256 elapsed) external view returns (uint256);
function currentSeatPrice() external view returns (uint256);
function takeSeat(uint256 agentId) external payable returns (uint256 price);
function sell(uint256 amount) external;
function quoteSell(uint256 amount) external view returns (uint256);
function quoteFee(uint256 priorSwaps, bool seatHolder) external pure returns (uint256);
function swap(bool bnbIn, uint256 amountIn, uint256 agentId, uint256 minOut)
    external payable returns (uint256 amountOut, uint256 feeBps);
```

状态：`openBlock`、`windowBlocks = 160`、`guardBlocks = 16`、`capSeats = 100`、`filled`、`reserve`、`seats[window] = {agentId, taker, filled}`、`idUsed[agentId]`、`congestionBlock`、`swapsInBlock`、池子的 `tokenReserve` 和 `bnbReserve`。没有 owner，没有改参数的函数。

每一块：

```text
delta = block.number - openBlock - 16
window = delta / 160
elapsed = delta % 160
span = 159
price = floor(filled) * (span + (span - elapsed)) / span
```

`elapsed = 0` 时价格正好是 `2 * floor`。`elapsed = 159` 时价格正好是 `floor`。中间整数除法向下取整，用户付的不会高于这个式子。`block.timestamp` 不参与。

本窗口席位本人在这一窗里交换，拥挤加价为 0。窗一结束，这个优惠消失。其他人如果持有自己的 Agent ID，付一半拥挤加价。费率上限 100 bps，也就是 1%。

离不开 Agent ID：席位记录的是 `tokenId`，不是地址。一个窗口的公开结果是「这块时间属于哪个 Agent ID」。没有这个 id，`takeSeat` 和 `swap` 都没有合法参数。第一册那种 `balanceOf > 0` 的布尔门在这里不够，因为合约要知道是哪一个 id 坐了这一窗，并且拒绝同一个 id 再坐。

防刷、防机器人：

- 一 id 一席，一窗一座。空窗跳过，不给「失败也算交互」留位置。
- 没有积分、没有推荐返还、没有按成交额累的奖励。页面不提示用户为了次数去发交易。
- 开册 16 块内不能占席，部署交易同一块里的跟单无效。
- 衰减让「最快」变得更贵，而不是更便宜。机器人当然仍可以在最后一块付地板。风险提示写明：临近地板时，这一席可能被区块构建者成交。人如果想自己成交，就在窗口前半段付溢价，把这个选择看成成本，不看成策略号召。
- 第 0 席地板 0.0015 BNB。按 0.05 gwei，一笔入席的气费大约是这个地板的百分之一量级，气费本身不是构建者抢排序的理由。抢的是席位：临近地板时少付溢价。靠近第 99 席时地板约 0.1 BNB，这个差更大。界面要写出「最后一块可能被构建者成交」，并随当前价和地板一起显示，不要用错的气费比较盖住这件事。
- 不设 `tx.origin` 限制，避免误伤合约钱包，也不把这个限制当成防机器人手段。

### 方案 C · 开放衰减

价格公式和方案 B 一样，窗口也是 160 块。差别是：一个窗口里每个还没入册的 Agent ID 都可以铸 1 枚，没有「这一窗只能一个人」。谁先付，谁就按当时那一块的价格成交。后面的人仍能在同一窗里付更低的价格，直到 100 枚铸完。

用户看到的是一条往下走的价格，以及「本窗已有多少个身份成交」，而不是一个独占的名字。倒计时结束时价格回到下一席的 2 倍地板——若这一窗已经铸了多枚，下一窗开头的地板跟着 `filled` 升高。

一次流程：

1. 连接自己的钱包，核对 `agentId`。
2. 看当前衰减价格、本窗已经成交的身份数、自己是否已经入册。
3. 调用 `mintAtDutch(agentId)`。保护期内回退。已用过的 id 回退。满 100 回退。
4. 支付拆分与方案 B 相同：地板进储备，溢价进死地址。
5. 卖回和交换与方案 B 相同。费率折扣给「已经入这一册的 id」，因为没有唯一席位。

合约：

```solidity
function mintAtDutch(uint256 agentId) external payable returns (uint256 price);
function windowFill(uint256 window) external view returns (uint256 count);
```

状态比 B 少一张「唯一席位」表，多一个 `fills[window]` 计数。每一块的价格式子与 B 相同，但不读取 `seats[window].filled` 来拒绝第二个人。

离不开 Agent ID：仍然是一 id 一枚，`tokenId` 写进名册。少了「这一块时间只属于一个 id」这一层，身份是资格，还不是这一窗的标题。

防刷、防机器人：一 id 一枚挡住了同一个身份来回铸。同一窗里的竞争回到了「谁先把交易放进块」，衰减只是让后来者付得更少，所以最快的机器人买在最贵的位置。这比方案 A 更劝退抢跑，也比方案 B 更容易在短时间里集齐多个地址，因为不需要等下一个 72 秒。仍然不设计失败交易奖励，不设计成交量奖励。开册 16 块保护照旧。

风险和 gas：同一窗里连续多笔铸会堆在少数块上，拥挤费和构建者排序同时出现。gas 与 B 同级。用户容易误解成「晚一点一定更便宜还能买到」——100 枚铸完就停，晚到的窗可能已经没有额度。文案要写「价格在这一窗里下降，额度是整册共享的，先铸完的人会把后面的席位用掉」。

## 8. 原型证明了什么

当时的原型在 `src/proposal/TurnSeatBook.sol`，只证明按块逻辑，池子不能按份额撤出，不要部署。方案 B 现已落成第二册：`src/TurnSeatFactory.sol`、`src/TurnSeatBook.sol`、`src/TurnSeatPool.sol`。窗口 160 块、保护 16 块写死。铸只允许整 1 枚，卖回至少 1 整枚。一个 tokenId 整册一席。池子 `beforeSwap` 改费率，并可以按份额撤出。`script/deploy-seat.sh` 只写待签文件，不广播。下面几条是原型已经证明、生产测试继续覆盖的行为。

已经跑通的行为：

- 第 0 席地板是 0.0015 BNB，第 1 席是 0.0025 BNB，第 99 席是 0.1005 BNB，与第一册积分一致。
- 保护期内 `takeSeat` 回退。保护期结束后窗口从 0 起算，每块价格下降，最后一块等于地板，下一块进入下一窗并回到新的 2 倍地板。
- 同一窗第二个人回退。空窗不增加 `filled`。下一个窗换一个 id 可以成交。同一个 id 再坐回退。
- 用别人的 id、id 为 0、付款不足，都会回退。
- 在窗口第 0 块占席：溢价等于地板，死地址余额增加这块溢价，曲线储备只增加地板。卖出 1 枚退回地板，溢价不退。合约里的 BNB 余额与储备一致。
- 连续三席以不同的窗内位置成交之后，储备等于整段供给的卖出积分。
