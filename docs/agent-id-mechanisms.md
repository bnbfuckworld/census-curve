# 绑定 Agent ID 的发行与炒作

本文替换上一版方案。上一版的保管、托管、分账、继任和罚没全部作废，下文不沿用那些状态机。

这次只讨论一件事：在 BNB Smart Chain（`chainId` 56）上，用一种普通「项目方铸币再加税」做不到的方式发行资产，并且发行出来的资产能在池子或订单簿里交易、形成价格、让人有理由买卖。每条路径都要求调用者此刻持有 SPACE ID Agent ID。没有就整笔回滚。

注册表：`0x60B9262456dE011F7d15a54CdD8c48bAaa8B022F`  
名称 `SPACE ID Agent ID`，符号 `AI`。持有判定是 `balanceOf(address) > 0`。调用前地址必须不是零地址。

Agent ID 只能在币安 App 内领取。本方案不代领、不保管助记词、不放官方标识，也不是该名称的发行方。

第 1 条「身份配额曲线」已有合约、测试和默认不广播的部署脚本，见 `docs/census-curve-v1.md`。第 2 到第 4 条仍只是设计。不要在未验收时传入 `--broadcast`，也不要把私钥写入仓库。

## 第一优先

先做 **身份配额曲线**。

发行规则是「每个 Agent 一份只减不增的铸额，卖出不恢复，后来者的铸额更小」。铸额用完之后，多出来的需求只能去恒定乘积池。池价可以离开曲线赎回价，这个价差就是炒作。创建者没有额外铸币权，也没有税率。

它不依赖预言机，没有到期日，也没有订单簿撮合。另外三条分别要处理地板价撮合、统一价退款，或外部价格。它们都值得做，但不该作为第一份要审计的代码。

| 顺序 | 名称 | 发行新在哪 | 炒作发生在哪 |
| --- | --- | --- | --- |
| 1 | 身份配额曲线 | 终身铸额按人封顶，卖出不恢复，后加入的人铸额更小 | 曲线赎回价之外，另有一个可以偏离的池 |
| 2 | 铸币订单簿 | 没有「铸给自己」的函数；新供给只在别人吃掉铸币卖单时出现 | 同一本订单簿上的买卖价 |
| 3 | 统一价拍卖 | 每人一份，全体付同一个价；创建者拿不到成交额 | 结算后按成交价启动、随后自由浮动的池 |
| 4 | 拆分二元 | 把 BNB 拆成 YES 和 NO，而不是增发项目币 | YES/BNB 与 NO/BNB 两个池的价格 |

## 共同约束

写函数遇到下面任一情况就回滚，不改道、不降级：

1. 参数地址是零地址。停在这里，不调用 `balanceOf`。
2. `balanceOf(account) == 0`。
3. `balanceOf > 0` 但 `handleOf` 为空。
4. 注册表调用本身回滚。

只认本笔交易的 `msg.sender`。不认 `tx.origin`，不认登录会话。Agentic Wallet 可以用来发交易，发到链上之后仍走这四条。

铸造的接收方如果是零地址，视为销毁，不对零地址查余额。转入零地址直接回滚。

池合约和订单簿合约自己没有 Agent ID。每个代币在创建交易里写下唯一的豁免地址，之后不能改。豁免地址可以暂存库存；用户的转入、转出、兑换、挂单、吃单、赎回仍要求用户是 Agent。除此以外，没有管理员能跳过检查，也没有升级代理。

创建者只能定名称和符号。斜率、铸额、地板、时长、行权比较的预言机地址，全部是工厂常量。没有创建者税，没有暂停键。

手续费若存在，只进该池的流动性提供者。不另设金库抽成。

失去 Agent ID 之后，退款和撤单也回滚，资金留在合约里。不设公共清算人，避免造出一条没有 Agent ID 也能把钱转走的路。

```solidity
error ZeroAccount();
error NotAgent();
error EmptyHandle();

function _agent(address account) internal view {
    if (account == address(0)) revert ZeroAccount();
    if (AGENT.balanceOf(account) == 0) revert NotAgent();
    if (bytes(AGENT.handleOf(account)).length == 0) revert EmptyHandle();
}
```

`AGENT` 写死为 `0x60B9262456dE011F7d15a54CdD8c48bAaa8B022F`。正式字节码同时要求 `block.chainid == 56`。测试用继承的 harness 注入 mock，harness 不进入发布产物。mock 要计数：失败路径上 `balanceOf` 的参数不能是零地址。

只读核对（2026-11-23，`eth_call`，未广播）：`chainId` 为 56；`name()` 为 `SPACE ID Agent ID`；`symbol()` 为 `AI`；`maxLen()` 为 20；`balanceOf(address(0))` 在注册表内回滚。注册表仍有 `owner`。本文不假设管理权已放弃，每笔状态变更都重新读取。

## 1. 身份配额曲线

**发行方式新在哪。** 初级供给来自一条有偿付能力的曲线，但每个 Agent 能从曲线买到的数量在第一次铸币时锁死，卖回曲线或在池子里卖掉都不恢复。锁定额度等于 `quota0 * SCALE / (SCALE + n)`。`n` 是已经锁定额度的 Agent 人数，只增不减。`SCALE` 取 100：第一个人拿到全额，第 100 个人开始拿到一半，再往后更小，小到不足最小单位就停止初级发行。曲线公式不看 `n`，所以后加入者变小的额度不会把赎回价算穿。

边际价格是 `slope * supply + base`。从供给 `s0` 买到 `s1` 的 BNB 成本是 `slope * (s1^2 - s0^2) / 2 + base * (s1 - s0)`。卖回用同一公式，退款向下取整，余数留在曲线里。因此曲线里的 BNB 始终够付下一次按公式卖回。

创建者与其他人使用同一额度，没有预留。

**Agent ID 为什么不可少。** 额度的主键是 Agent 地址。没有这道一人一枚、转不走的检查，同一人可以用任意多个地址重复领取早期的大额度，曲线的人数衰减就没有意义。池子兑换、添加和移除流动性的调用者也必须是 Agent。代币在用户之间转移时，双方都必须是 Agent；唯一例外是创建时写死的那个池地址。

公开资料把这枚 NFT 描述为不可转让、每人一枚。额度「买不走」依赖这个外部事实。合约能强制的是：此刻 `balanceOf == 0` 就不能铸、不能换、不能转给无 ID 的地址。

**炒作怎么发生。** 同时存在两个价。曲线价是按公式算出来的赎回价，受额度限制。池价是恒定乘积池里的成交价，不受额度限制。额度用完的人若还想加仓，只能向池子买，可以把池价买到曲线价之上。手里有币的人可以卖给池子，也可以卖回曲线。池价高于曲线价时，仍有剩余额度的人会从曲线铸造再卖进池子；池价低于曲线价时，会有人从池子买入再卖回曲线。价差本身就是交易理由。初级发行停掉之后，池子继续交易，价格只由池子决定。

池子手续费 0.3%，记入 LP 份额。第一笔流动性由任意 Agent 自愿添加。曲线赎回在没有流动性时也成立，所以开盘不依赖项目方注资。

**风险与滥用。**

- 一个人若持有多个币安账户，就能锁多份早期额度。合约无法识别链下同一人。剩下的成本是领取 Agent ID 的账户成本。
- 池子可以被对敲。对敲不增发，但会制造虚假成交。
- 取整必须总是让曲线少付钱。实现要用能检查溢出的乘法，并在测试里覆盖「卖回金额不超过曲线余额」。
- 豁免地址若能被换成攻击者的合约，转移检查就失效。豁免地址只能在创建交易里写一次。
- 创建者不能改斜率。斜率、`quota0`、`SCALE`、`base` 都是工厂常量，避免用参数做成隐蔽抽成。

**最小可上线范围。**

- 工厂常量决定经济参数；`create(name, symbol)` 部署一套独立的代币、曲线和池。
- 写函数：`mint`、`sell`、`swap`、`addLiquidity`、`removeLiquidity`。
- 代币转移检查双方 Agent 身份，池地址除外。
- 无管理员、无税、无直接把币铸给调用者且不受额度约束的函数。
- 测试：无 ID 时铸造、卖出、兑换、转账都回滚；未知路径不调用 `balanceOf(0)`；卖出不恢复额度；第二个人的额度小于第一个人；卖回后曲线余额仍非负；池价可以高于曲线价，且额度用尽的地址仍能在池子买入。

### v1 代码对照

实现在 `src/`。供给以 wei 记账，`slope` 和 `base` 是「每一整枚代币」的 wei。整枚数量 `U = s / 1e18` 时，从 0 到 `U` 的 BNB 是 `slope * U^2 / 2 + base * U` 的向下取整。从 `s0` 买到 `s1` 收取 `target(s1) - target(s0)`，因此拆成多笔和一次买进的总额相同，卖回支付同一段差额，不会超过曲线里已经入账的 BNB。全额卖回后账面余额回到 0；除法丢掉的余数从未收进来，所以不会在卖出时多付。

生产工厂把这些数写死：`SLOPE = 1e15`，`BASE = 1e15`，`QUOTA0 = 100 ether`，`SCALE = 100`。0 供给时边际价是 0.001 BNB/枚，100 枚时是 0.101 BNB/枚，第一名的 100 枚铸额积分成本是 5.1 BNB。创建者改不了这些数。测试工厂在 `test/harness/`，只注入 mock 和测试用的斜率、铸额、底价，不进入发布字节码。

## 2. 铸币订单簿

**发行方式新在哪。** 没有面向自己的铸造函数。新代币只在一种情况下出现：某个 Agent 挂出「铸币卖单」，另一个 Agent 以不低于地板的价格把它吃掉。成交额归挂单者。挂单者每纪元最多成交一份，一份的大小是工厂常量。地板价等于 `base * (已铸份数 + 1)`，只升不降。市场上的成交价可以跌破地板，但跌破之后新的铸币卖单不能再成交，增发自动停下。

同一本订单簿上还有库存卖单和买单。库存卖单卖的是已经存在的币，不增发。三种单每个 Agent 同时最多各挂一张。吃单时在有上限的数组里找最优价，不使用链下撮合器。

**Agent ID 为什么不可少。** 铸币份数、挂单资格和吃单资格都按 Agent 计。没有这道检查，攻击者可以用两个新地址以地板价左右手成交，按纪元无限增发。撤单同样要求 Agent。订单簿合约是唯一可以暂存库存代币的非 Agent 地址，地址写死后不能换。

**炒作怎么发生。** 价格就是订单簿上的最高买价和最低卖价。投机者可以吃掉便宜的库存卖单，也可以挂更高的卖单离场。铸币卖单是新供给的唯一入口，而且不能低于地板。所以现货跌破地板时，市场上只剩存量博弈；价格重新站上地板时，新的一份才可能被买出来。挂单者按成交额结算，买家承担下一笔成交价变动的风险。这只是成交金额的分配，不是承诺的利息或分红。每人每纪元只有一份，而且必须有另一个 Agent 愿意买。

纪元长度、每份大小、每纪元全局最多成交的铸币份数、地板的 `base`，都是工厂常量。全局上限用来限制「很多 Agent 同时铸」带来的稀释速度。

**风险与滥用。**

- 两个 Agent 仍可以在地板价自买自卖，把新供给铸出来。伤害是稀释，不是从别人的储备里提走 BNB。全局每纪元份数上限把速度封住。
- 链上线性撮合在挂单接近上限时更贵。第一版把全部未成交单限制在一个小常数内，满了就拒绝新挂单。
- 挂单后失去 Agent ID 的人不能撤单，库存或保证金留在合约里。这是失败关闭，不是意外分支。
- 吃单和撤单都要防重入。BNB 与代币先改记账，再对外转账。

**最小可上线范围。**

- 一个工厂、一种代币、一本订单簿。固定份量，第一版不成交零头。
- 写函数：`postMintAsk`、`postAsk`、`postBid`、`cancel`、`take`。
- 测试：不能把币直接铸给自己；低于地板的铸币卖单回滚；库存卖单不增加总供给；同一 Agent 在同一纪元不能成交第二份铸币卖单；无 ID 不能挂、不能吃、不能撤；`balanceOf(0)` 不被调用；总供给增加量等于被吃掉的铸币份数。

## 3. 统一价拍卖

**发行方式新在哪。** 供给在一段时钟内只通过申购发出。时钟价格从工厂常量的高点线性降到低点。每个 Agent 最多 `take()` 一次，先按当时的时钟价锁住 BNB，先不拿币。时钟结束或份数卖完时，任意 Agent 可以调用结算。成交价是结束时的时钟价，所有成功申购者都付这个价，多锁的部分退回本人。没有人能买两份，也没有人因为下手早而付得比别人贵。

创建者得不到成交额。任意 Agent 都可以调用结算。结算把全部成交额，连同数量相等的新铸代币，做成池子的初始流动性，并把这张 LP 凭证永久锁在合约里，没有赎回函数。申购者拿到的代币总量等于池中初始代币总量。开盘价等于统一成交价，之后由买卖推动。

拍卖进行中的申购收据不能转让。结算之后的代币可以转让，这才是被炒作的资产。

**Agent ID 为什么不可少。** 一人一份依赖 Agent 不能被批量制造。没有这道检查，一个地址就可以在时钟上扫走全部份数，统一价和「同一成交价」都会退化成普通抢购。结算退款、之后的池子兑换和转账，同样要求 Agent。池地址是唯一豁免，且没有移除流动性的入口。

**炒作怎么发生。** 申购阶段赌的是最终成交价会落在自己能接受的位置，并且结算后的池价会高于成交价。结算完成后，池子立即可以买卖。想买第二份的人只能向池子买，把价格买高。想离场的人把第一份卖进池子。锁定的底池提供深度，也构成稀释：刚结算时，申购者合计持有一半供给，另一半在池中。这个比例是深度的来源，要写进界面，不能当成隐藏税。

**风险与滥用。**

- 一半供给进池，是明确稀释。若需求起不来，池价可以低于成交价，申购者亏损。
- 时钟末端会拥挤。一人一次把单地址抢跑限制住，但不能消除同一人多账户。
- 结算前失去 Agent ID 的申购者不能领币，也不能领退款，资金留下。
- LP 永久锁定意味着这笔 BNB 不能再被任何人取走，只能通过交易换手。界面必须先说明，再让用户 `take()`。
- 时钟参数写死在工厂里，创建者不能把时钟设成极短来方便自己的账户。

**最小可上线范围。**

- `create(name, symbol)` 后只有 `take` 与 `settle`，外加结算后的 `swap`。
- 不实现可转让的申购收据。
- 不实现移除初始流动性。用户之后自愿添加的流动性若要支持撤出，必须是另一张 LP，且撤出只能拿回该用户自己添加的部分；第一版可以不做第二张 LP，只保留初始锁定池和 `swap`。
- 测试：同一 Agent 不能 `take` 两次；两个 Agent 的成交价相同；多锁的 BNB 只退给本人；创建者余额不增加；无 ID 不能申购、不能结算领币、不能兑换；结算后池价可以从成交价被买高；初始 LP 没有转出函数。

## 4. 拆分二元

**发行方式新在哪。** 用户交给合约 1 BNB，同时得到 1 枚 YES 和 1 枚 NO。这不是项目币增发。结算前，交回 1 YES 加 1 NO 可以取回 1 BNB，此时总 YES 供给、总 NO 供给和抵押 BNB 三者相等。结算成功后不能再合并。比较成立则每枚 YES 兑 1 BNB、NO 兑 0；不成立则相反。每赎回一枚胜出代币，抵押减少 1 BNB 并销毁该代币；失败代币赎回时只销毁。胜出供给在结算当下等于抵押，所以兑付有足额 BNB。

第一版只做一种比较：到期时 Chainlink BNB/USD 是否大于等于创建时写死的行权价。工厂把聚合器地址固定为 `0x0567F2323251f0Aab15c8dFb1967E4e8A7D42aeE`。2026-11-23 的只读调用确认它的 `description()` 是 `BNB / USD`，`decimals()` 是 8，`latestRoundData()` 能返回正价格。创建者不能改地址，只能在工厂允许的范围内选行权价和到期时间。

每个 Agent 通过 `split` 锁进的 BNB 有工厂常量上限。超过上限的方向性仓位只能向池子买。

**Agent ID 为什么不可少。** 拆分上限按 Agent 计。没有这道检查，一个交易者可以用无限地址拆出无限 YES 并在池子里砸价，上限就失效了。合并、兑换、赎回和添加流动性都要求调用者是 Agent。YES 与 NO 的转移双方都要是 Agent，各自的池地址除外。

**炒作怎么发生。** YES/BNB 与 NO/BNB 各有一个恒定乘积池，手续费 0.3% 给该池 LP。认为到期价会高于行权价的人买 YES 或卖 NO，反方向的人做相反的事。池价会偏离 0 和 1，偏离就是对结果的定价。完整套装可以合并回 BNB，所以 YES 与 NO 的套利和方向性持仓是两条不同的交易。结算后胜出代币按 1 BNB 赎回，失败代币赎回为 0。池子库存由池合约自己赎回：胜出库存变成池内 BNB，失败库存归零，LP 再按份额取回剩余资产。

结算读取 `latestRoundData()`。价格必须为正，`updatedAt` 距当前时间不能超过工厂常量，`answeredInRound` 不能落后于 `roundId`。任一条件不满足，结算回滚。到期后再过 24 小时若仍然没有合格价格，完整套装可以继续合并取回 BNB；只持有一边的人不能靠这条路径兑付。没有管理员能改结算结果。

**风险与滥用。**

- 预言机是这条机制的主要风险。价格源出错、停更或被替换时，方向性持仓可能既不能结算，也不能单独退回。完整套装持有人在宽限期后可以合并。因为喂价地址写死且没有管理员，喂价作废时已创建的市场不能改接到新合约。
- 池价可以被资金推动，但结算只看喂价，不看池价。用池价操纵结果这条路不存在；操纵喂价的风险留在 Chainlink 一侧。
- 拆分上限挡不住「在池子里买超额 YES」。上限限制的是初级发行，不是二级仓位。
- 两个池加上赎回，分支比前三条多。测试必须覆盖「YES 胜、NO 胜、喂价过期、只持有一边、池内库存赎回」五种结算。

**最小可上线范围。**

- 工厂固定聚合器地址。`create(strike, expiry)` 只接收范围以内的两个参数。
- 写函数：`split`、`merge`、两个池的 `swap` 与流动性函数、`settle`、`redeem`。
- 不做自定义题目，不做多档行权价，不做部分抵押。
- 测试：拆分后抵押、YES 供给、NO 供给三者相等；合并后三者一起减少；无 ID 不能拆、不能换、不能赎回；`balanceOf(0)` 不被调用；喂价过期时 `settle` 回滚；宽限期后完整套装仍可合并；胜出一方按 1 BNB 兑付且合约余额足够。

## 本批不做的事

- 不做创建者预留、转账税和可更换的收费地址。
- 不做签到、积分和按时间发产量。
- 不把登录签名当成发行或成交。
- 不在第一版把四条机制合成一个合约，也不让它们互相调用。
- 不代领 Agent ID。

## 实现时怎么验收

从身份配额曲线开始。发布字节码写死 `chainId` 56、注册表地址和经济常量。部署脚本默认不广播。需要主网数据时，产品柜台读 BSC 主网 RPC；开发演练仍只在回环上做。

每条机制单独验收：无 Agent ID 的写路径回滚、零地址不会进入 `balanceOf`、发行规则不能被创建者改掉、二级市场能把价格打到与初级发行价不同的位置。
